# Token 与成本

负责：开发侧与运行侧的 Token/成本策略、成本模型、上下文结构、记账口径。
上游：`docs/memory.md`（窗口与摘要）、`docs/tools.md`（输出上限）。
改动影响：改动窗口/上限/模型档位时同步 `docs/architecture.md` 模块职责。

## 1. 两条预算必须分开管理

| 预算 | 谁在花 | 主要杠杆 |
|---|---|---|
| 开发 Token | Coding Agent 读写代码/文档/日志 | 最小 diff、只读必要文件、契约固定、文档路由 |
| 运行 Token | 群宠实际调用 API | 闸门拦截、动态窗口、工具节制、输出截断、缓存命中 |

两者不要混在同一个账户里核对；`usage` 表只统计运行侧。

## 2. 开发侧规则（省"读"和"重写"）

1. 任务开工只读 `docs/README.md` 路由表指向的 1–3 个文件（见 `architecture.md` §3 模块地图定位代码）。
2. 只读必要片段：用行区间/关键词定位，禁止整仓扫描、粘贴整份日志。
3. 最小 diff，不整文件重写；不顺手重构无关代码。
4. 契约（工具、表结构、权限）固定后不再重复确认；文档不重述已确认结论。
5. 测试通过即停止；汇报只写四件事（改了什么/测了什么/结果/已知问题）。
6. 新增输出尽量短：默认安静模式，不打印大段中间结果。

## 3. 运行侧：四链 + 一杠杆

**链 1 · 入口**：硬规则先过滤。不值得回应的消息 **0 token**（不调用模型、不构造上下文）。
不确定才进入模型判断，且判断本身只用规则，不额外调用分类模型。
私聊默认完全不处理，同样 **0 token**（见 `docs/requirements.md` §2.2）。
被冷却或每窗口上限压住的候选消息（`wait`）同样 **0 token**：只入库，不回应（见 `docs/requirements.md` §2.1）。

**链 2 · 上下文**：动态窗口 + 噪声过滤 + 模板化摘要 + 按需检索（见 `docs/memory.md`）。
Prompt 结构固定为"固定段在前、动态段在后"：

```
[固定，字节稳定]  全局人格（docs/persona.md） → 群设定 → 工具清单 → 输出规则
[动态]            摘要/检索 → 最近消息（升序，本轮边界快照） → 本轮待处理消息 →（可选）当前情绪
```

- **当前情绪**：来自最近一次贴纸（`app/session/mood.py`），进程内存、TTL 10 分钟、重启清空；为空不注入，注入时只多一行。
- **记忆块**：固定段之后、历史窗口之前的一条 system 消息（`## 记忆`）= 最新摘要（≤300 字）+ 命中片段（≤3 条 / ≤800 字符）；无内容则整块不注入。动态段总预算约 6000 字符（`HISTORY_BUDGET_CHARS`），超预算从最旧历史丢，本轮消息永不丢。

- **本轮边界**：模型调用期间新到的消息不并入本轮，只落库；本轮结束后合并为下一轮一批（≤5 条），
  避免"边思考边被新消息打断"，也避免为每条新消息各生成一次调用。

**链 3 · 工具**：能不用就不用；参数与结果都短；失败只回结构化错误（≤200 字符）；
工具轮次按意图分档：

| 意图 | 最大工具轮次 |
|---|---|
| 闲聊/知识问答 | 0 |
| 简单计算或单次查询 | 1 |
| 需要多步的任务 | 2 |
| 代码调试 | 4（另有总时长与成本上限） |

阶段 3 实现：`TOOL_MAX_ROUNDS=2`（最多 2 轮工具 + 1 次收尾调用，总调用 ≤3）；**当前状态（2026-10-07）**：已在 `app/llm/routing.py::tool_round_limit` 落地按意图分档（闲聊 1 轮，其余沿用全局 `TOOL_MAX_ROUNDS`，见 §5.2）。表里的「闲聊/知识问答 = 0」没有照做——0 轮意味着该轮**完全不下发工具**，会连贴纸工具（`send_sticker`）一起关掉；「简单计算或单次查询 = 1」也没有单独下调，因为 default 意图覆盖普通任务里常见的 read→write 两步链，降到 1 会产出半成品回复。

**链 4 · 输出**：只输出给用户看的最终内容，不输出内部分析与过渡语；
能一句话就一句话；允许 `{"action":"ignore"}` 完全不说话。

**一杠杆 · 缓存命中**（已核实的真实价格，`deepseek-flash`，单位 1M tokens）：

| 项 | 非高峰 | 高峰 |
|---|---|---|
| 输入（缓存命中） | $0.003 | $0.006 |
| 输入（缓存未命中） | $0.15 | $0.3 |
| 输出 | $0.6 | $1.2 |

- 命中缓存比未命中**便宜 50 倍**：固定前缀必须字节稳定（全局人格/群设定/工具清单/输出规则顺序固定），
  任何易变内容不得插入固定段；当前情绪等易变内容放在动态段末条（见 `docs/persona.md` §2）。
- 高峰时段为周一至周五 01:00–04:00 与 06:00–10:00 UTC（其余时间含周末为半价）。
- 不可缓存的正确性依赖：工具清单顺序、群设定渲染顺序、摘要插入位置都要稳定。
- 例外：工具清单在本轮内可能变短——某工具本轮被禁用或熔断后，下一次模型调用不再下发它（见 `docs/tools.md` §1）。那一轮会失去前缀缓存，但省下一整轮模型调用，且只在已经出现工具失败后才会发生。

来源：[DeepSeek Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing)。模型名：`deepseek-flash`、`deepseek-v4-pro`（旧名 `deepseek-v4-flash` 已映射到同一模型）。

## 4. 记账口径

`usage` 表（见 `docs/database.md`）每次调用记录：`model`、`input_tokens`、`cached_tokens`、
`output_tokens`、`tool_calls`、`tool_ms`，按 `chat_id` + `day` 聚合。
用途：判断哪条链最贵（是上下文太长、工具太多，还是缓存没命中），而不是"感觉贵"。

### 4.1 配额（阶段 8 F5.3）

- 两个全局键：`QUOTA_DAILY_TOKENS` / `QUOTA_MONTHLY_TOKENS`，**按 `chat_id` 分别统计**（不新增 `chat_settings` 字段，配额是部署方的决定，不是群主的开关）。
- `0` 或未配置 = **不限额**（与 `SEARCH_BACKEND=none` / `SANDBOX_BACKEND=none` 的"关闭"写法一致）。
- 统计口径：该群 `usage` 表中 `input_tokens + output_tokens` 的合计（`cached_tokens` 已包含在 `input_tokens` 里，不重复计入；摘要等后台调用同样花该群的钱，一并计入）。日 = `TIMEZONE` 的自然日，月 = 自然月（`day` 的 `YYYY-MM` 前缀）。
- 检查发生在**调用模型之前**：达到或超过上限（`>=`）时本轮不调用模型、不记账、不写入 Bot 发言，只回一条提示（日/月各一句，不含数据库或实现细节）。
- 判定只读 `usage`，不写库、不缓存、不额外记账，因此正常轮次不会因为检查而多出记账行。

## 5. 模式（阶段 8）

| 模式 | 窗口 | 工具 | 输出上限 | 贴纸 |
|---|---|---|---|---|
| economy | 最小（10 条） | L0 只读 | 短 | 关 |
| normal | 默认（20 条） | 群设定允许的等级 | 正常 | 开 |
| smart | 最长（50 条） | 允许的等级 + 更多工具 | 正常 | 开 |
| unrestricted | 最长 | 全部（管理员） | 不限 | 开 |

实现口径（阶段 8 F5.1 已落地，唯一权威表 `app/modes.py`）：

- **窗口**：economy 固定 10 条、smart / unrestricted 固定 50 条；normal 不固定，沿用原有按意图分档（复杂 50 / 闲聊 10 / 默认 20，`docs/memory.md` §2）。模式窗口优先于意图分档，未知模式按 normal 处理。
- **输出上限**：economy 短（256 tokens），normal / smart 用 `LLM_MAX_OUTPUT_TOKENS`（默认 1024），unrestricted 不发送 `max_tokens`（不限）。
- **工具档位**：economy 只放 L0（群开关仍然生效）；normal 完全由群开关决定；smart 在群开关之上额外放行 L0 只读工具；unrestricted 放行全部已注册工具、不看群开关。贴纸只有 economy 关。
- **谁能改模式**：只有群管理员能通过 `/settings mode <值>` 修改（`docs/security.md` §2.1）；改完对下一条消息立即生效，不需要重启。模型不能提升自己的权限：模式决定的是「上限」，注册表、schema 校验、超时、沙箱仍是硬约束。
- 仍未做：无（链 3 的工具轮次分档已实施，见 §5.2）。

### 5.1 模型档位路由（已实施）

最小规则型路由，唯一入口 `app/llm/routing.py::ModelRouter.choose(intent=..., purpose=...)`（Web / Service Layer 以后复用同一入口）：

- **默认档** = `LLM_MODEL`（当前 `deepseek-flash`）：普通聊天、summary / 后台任务、无法判断复杂度的任务、未配置强模型、选择过程出错，全部用默认档。
- **升级档**（可选）：只有当纯规则意图判定为复杂（代码块 / 单条 ≥400 字 / 含链接 / 检索类措辞，见 `app/session/context.py::ContextBuilder.intent`）**且**配置里存在另一个更强模型（`LLM_MODEL_STRONG`，留空 = 未配置）时，才用 `LLM_MODEL_STRONG`；与默认同名视为未配置。
- **不做**：不因路由增加一次 LLM 判断、不新增 AI 分类器、不引入新依赖；路由只决定模型名。
- **fail-safe**：选择逻辑任何异常都回退默认档（`LLM_MODEL`）。
- **不绕过约束**：配额在路由之前判定，工具档位（§5 工具）、沙箱、权限与安全规则都在路由之外——路由只换模型名，不改变它们的判定。
- **记账**：`usage.model` 记最终实际使用的模型（`app/llm/loop.py` 用路由结果发起调用，响应回传的模型名覆盖它）；`purpose` 保持既有口径（chat / summary）。
- 意图分档与模式无关：economy 下复杂任务同样按复杂度升级，模式仍只管窗口 / 输出上限 / 工具档位（§5 各表不变）。
- 成本影响：`LLM_MODEL_STRONG` 留空时行为与成本与升级前完全一致；填了之后只有规则判定为复杂的轮次会换模型，且**缓存按模型隔离**——升级轮命中不了默认档的缓存，那一轮可能按未命中价计费（§3 一杠杆）。

### 5.2 工具轮次分档（已实施）

同一入口 `app/llm/routing.py::tool_round_limit(intent, settings)`，`app/session/runner.py` 每轮把它作为 `Responder.reply(max_rounds=...)` 传入：

| 意图 | 实际工具轮次 | 与 §3 链 3 表的关系 |
|---|---|---|
| 闲聊 | `min(1, TOOL_MAX_ROUNDS)` | 原表写 0，实际取 1（见下） |
| 简单计算 / 单次查询 | 全局上限（默认 2） | 未单独下调（见下） |
| 需要多步的任务 | 全局上限（默认 2） | 与表一致 |
| 代码调试 | 全局上限（部署方设 4） | 表里的 4 轮 = `TOOL_MAX_ROUNDS=4` |

- **只调低、不突破**：未登记的意图（复杂任务、无法判断）与未知/异常输入一律返回 `max(0, TOOL_MAX_ROUNDS)`；分档取 `min(分档值, 全局上限)`，部署方把 `TOOL_MAX_ROUNDS` 设成 0/1 时闲聊不会更宽。
- **为什么闲聊是 1 不是 0**：0 轮会让该轮完全不下发工具，连 `send_sticker`（贴纸，F4.5）一起关掉——贴纸本来就靠模型在闲聊里主动发表情。1 轮既保住一次工具调用，又比默认档少一整轮；`tests/offline/test_pipeline.py::test_chitchat_still_offers_send_sticker` 钉住这条不回归。
- **为什么 default 不降到 1**：现有意图规则只有 complex / chitchat / default 三档，default 覆盖普通任务里常见的 read→write 两步链，无真实证据就下调会切成半成品回复；要「简单计算 1 轮」需要先有更细的意图规则，属后续任务。
- 记账不变：`usage.tool_calls` 与实际轮次一致（闲聊 1 轮 / 普通任务 2 轮 / `TOOL_MAX_ROUNDS=3` 时复杂任务 3 轮，三条端到端用例覆盖）。

## 6. 五条判定式

> 不该说的话不进模型。不需要看的内容不进上下文。不需要用的工具不调用。
> 不需要继续思考就立刻结束。改代码只做最小 diff。
