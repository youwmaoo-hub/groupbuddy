# 记忆与检索

负责：短期上下文窗口、噪声判定、摘要触发与模板、FTS5 检索策略。
上游：`docs/requirements.md` F3；表结构见 `docs/database.md`。
改动影响：窗口/阈值/模板变更会影响 `docs/token.md` 的成本结论。

## 1. 原则

**原文存储 ≠ 模型上下文。** 数据库可以保存一切，进入模型上下文的必须是有用的那部分。
检索是**补充背景**，不替代短期原文。

## 2. 短期窗口（ContextBuilder）

| 情形 | 默认条数 | 说明 |
|---|---|---|
| 普通问题 | 20 | 包含 Bot 自己的发言，按时间升序；实现见 `app/session/context.py` 的 `window_size()` |
| 复杂问题 | 最多 50 | 触发条件：出现长文本、代码块、或用户明确追问上文 |
| 纯闲聊 | 10 | 只保证不"失忆"，不追求连续性 |
| 硬约束 | 约 6000 字符（`HISTORY_BUDGET_CHARS`，字符近似，不引入 tokenizer） | 超预算从最旧的消息开始丢；本轮用户消息永不丢；被裁条数可用 `ContextBuilder.consume_trimmed()` 观测 |

- 窗口按 `chat_id`（未来 `thread_id`）过滤，绝不跨群（`messages.recent()` 已排除 `noise=1`）。
- **本轮边界**：窗口只取「处理这一轮时已入库」的消息（`id` 快照）；模型调用期间新到的消息留在库里，合并进下一轮。
- **私聊**：私聊消息默认不写入 `messages`，因此不进入任何上下文（见 `docs/requirements.md` §2.2）。
- 被丢掉的旧消息不影响已落库数据；需要时靠摘要与检索找回。

## 3. 噪声（noise）判定

入库时打标，用于决定"是否进入模型上下文"，不影响存储：

- 标记为噪声：纯表情、纯标点、长度 < 4 且无疑问词、常见无信息量短句（如"哈哈/草/666/笑死/确实/晚安"）。实现：`app/session/noise.py` 的 `is_noise()`，在 `runner.handle` 入库时判定并写入 `messages.noise`。
- 永不标为噪声：包含 `@`、问号、链接、代码块、报错关键词、或回复了 Bot 的消息。
- 噪声消息仍写入 `messages`（`noise=1`），但默认不进入上下文；若它是本轮待处理消息则不参与触发。

## 4. 摘要

触发条件（任一满足，异步执行，不阻塞回复）：

- 自上次摘要以来新增消息 ≥ 40 条；
- 群内静默 ≥ 2 分钟且期间有新消息；
- 上下文窗口即将超预算。

固定模板（模型只填空，不自由发挥）：

```
当前话题：
正在做的事：
已完成：
待完成：
偏好/约束：
关键实体（人名、项目名、文件）：
```

- 每个 `chat_id` 保留最近 1 条滚动摘要 + 历史摘要归档（每群保留最近 50 条）；只把最近的摘要放入上下文。
- 实现：`app/session/summary.py` 的 `SummaryService`（per-chat 锁、滚动输入=上次摘要+游标之后的消息、`msg_to` 作游标）与 `SummaryScheduler`（后台循环，`SUMMARY_POLL_SECONDS`）；失败不写库、不推进游标，重启后按游标续跑；摘要调用单独记 `usage.purpose='summary'`。
- 摘要必须短（默认 ≤300 字）；超出即重新压缩，不得逐条罗列消息。

## 5. 检索（FTS5）

流程：查询构造 → FTS 搜索（摘要 + 笔记）→ 去重 → 排序 → 预算内注入。

- 检索源：`summaries`、`notes`（不含全部原文，避免把旧消息重新灌回上下文）。
- 查询由当前用户消息的关键词构成（`app/session/retrieval.py` 的 `term_tokens()`：中文双字 bigram + 拉丁词）；不额外调用模型生成检索词（省 token）。
- 触发条件：出现回溯/指代信号词（之前/上次/刚才/那个/继续/接着/前面…），或短期窗口被预算裁剪且仍有未摘要历史；否则不检索。
- 检索只查 `summaries`/`notes` 的 FTS（`tokens` 列），SQL 强制带 `chat_id`：跨群召回属于缺陷。
- 注入上限：最多 3 条、总计 ≤800 字符；注入位置在动态段（见 `docs/token.md` §3）。
- 命中结果必须带来源（摘要 id / 笔记名），便于模型区分"记忆"与"当前对话"。

## 6. 笔记（notes）

- 长期事实（群规、偏好、项目状态）由群主命令或模型显式请求写入 `notes`。
- 每条笔记 ≤500 字；同名覆盖前保留旧版本号。
- 笔记是 FTS 的检索源之一；不默认全量注入上下文。
