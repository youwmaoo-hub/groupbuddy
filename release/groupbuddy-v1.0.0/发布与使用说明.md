# groupbuddy v1.0.0 · 发布与使用说明

本目录是 **groupbuddy v1.0.0** 的发布快照：一个单进程、单 Bot Token 的 Telegram 群宠机器人，
外加一个**可选**的本地控制面板。对应开发仓库提交 `61d3965`（打包口径与验收记录见包内 `docs/status.md` §4.13/§4.14），
本机离线验收 `Ran 688 tests / OK (skipped=2)`。

本文件回答三件事：**需要准备什么**、**怎么部署**、**怎么改**。契约细节以 `docs/` 为准（入口见 `docs/README.md`）。

---

## 1. 这个包里面有什么

```
app/            机器人本体（gate/ llm/ session/ tools/ sandbox/ outbound/ storage/ ops/ telegram/ domain/）
app/control/    控制面板（可选）：HTTP 适配器 + 零构建静态页，只经服务层
app/services/   服务层：面板与命令通道共用的唯一业务入口
tests/offline/  688 条离线用例（无网络、无真实 Token）
docs/           设计文档（架构、需求、安全、工具、数据库、部署、ADR 等）
deploy/         贴纸目录清单（不含素材本体）
scripts/        贴纸导入、数据库备份、沙箱验收脚本
.github/        GitHub Actions：离线测试 + 凭据/运行数据入库检查
README.md / CHANGELOG.md / CONTRIBUTING.md / SECURITY.md / LICENSE(MIT) / AGENTS.md / TODO.md
.env.example    配置模板（**占位值**，复制成 .env 后填自己的）
requirements.txt
```

**不包含**（发布时刻意排除）：`storage/` 与任何运行数据（`bot.db`、日志、workspace、备份）、真实 `.env`、
虚拟环境、贴纸素材本体、开发时的原始需求记录（`优化与前言.txt`、`流程与要求.txt`）。

## 2. 使用它需要准备什么

| 必需项 | 说明 |
|---|---|
| Python | **≥3.11**（开发与验收基线 3.13） |
| Telegram Bot Token | 找 [@BotFather](https://t.me/BotFather) 新建 Bot，拿 `123456:ABC…` 形式的 Token |
| LLM 服务 | 任何 **OpenAI 兼容**端点：一个 `base_url`、一个 `api_key`、一个模型名 |
| 操作系统 | Linux VPS（推荐）或 Windows/macOS 本地试跑 |

| 可选项 | 说明 |
|---|---|
| 容器运行时 | rootless **Podman** 或 **Docker**。只有 `run_code` 沙箱工具需要；没有它时该工具 **fail-closed 拒绝执行**，其余功能不受影响 |
| 控制面板 | 不需要额外服务；面板依赖 `fastapi` / `uvicorn`（已在 `requirements.txt` 中，属可选依赖），默认关闭 |
| systemd | Linux 上做 24/7 常驻与自愈（用户级单元即可，不需要 root 服务） |

群聊提醒：Telegram 默认给 Bot 开 **Privacy Mode**，群里不 @ 它、不回复它时消息根本不会推给进程，
主动接话不会生效——这是 Telegram 侧设置，按 `docs/deployment.md` §12.10 处理。

## 3. 安装

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt          # Windows: .venv\Scripts\pip
cp .env.example .env                               # Windows: copy .env.example .env
# 编辑 .env：至少填 BOT_TOKEN 与 LLM_API_KEY
.venv/bin/python -m app.main                       # Windows: .venv\Scripts\python -m app.main
```

`.env` 里最常用的键（完整清单见 `.env.example` 与 `docs/deployment.md` §3）：

| 键 | 默认 | 说明 |
|---|---|---|
| `BOT_TOKEN` | 无（必填） | BotFather 给的 Token；**永不入库、永不进日志** |
| `LLM_API_KEY` | 无（必填） | 你的 LLM 服务 Key |
| `LLM_BASE_URL` | 代码默认 `https://api.deepseek.com` | `.env.example` 里写的是占位端点 `https://api.example.com/v1`；**用别的服务就填自己的端点** |
| `LLM_MODEL` | `deepseek-flash` | 默认档模型名（示例值，填你自己的） |
| `BOT_ALIASES` | 空 | 让它认出自己的名字，如 `MyBot,小助手` |
| `TIMEZONE` | `Asia/Shanghai` | 统计与配额的“自然日”口径 |
| `PERSONA` | 空 | 部署侧全局人设，覆盖内置人格（优先级：本群 > `PERSONA` > 内置） |
| `SANDBOX_BACKEND` | `auto` | `auto`/`podman`/`docker`/`none`；探测不到时 `run_code` 拒绝执行 |
| `DATA_DIR` / `DB_PATH` / `WORKSPACE_ROOT` | `storage` / `storage/bot.db` / `storage/workspaces` | 所有运行数据都在这下面，备份只需盯这里 |

## 4. 部署（24/7）

- 目录与持久化、更新与回滚、备份与恢复、健康检查：**唯一权威是 `docs/deployment.md`**。
- Linux + systemd 用户级单元模板：`docs/deployment.md` §12.9（`Restart=always` + `KillSignal=SIGTERM`，
  开机自启用 `loginctl enable-linger`）；VPS 上线前的完整检查清单见 §12.1–§12.8、§13 与 `docs/security.md` §13。
- 数据库备份：`python scripts/backup_db.py`（冷快照 + `PRAGMA integrity_check` + 行数校验 + 保留份数）。
- 沙箱自检：`python scripts/verify_sandbox.py`（15 项，含能力集与提权位检查）。

## 5. 控制面板（可选）

默认**关闭**，不装、不开都不影响机器人；打开前后都只监听回环，远程访问走 SSH 隧道：

```bash
.venv/bin/python -c "import secrets;print(secrets.token_urlsafe(24))"   # 生成口令
# .env 追加：
#   PANEL_ENABLED=true
#   PANEL_HOST=127.0.0.1
#   PANEL_PORT=8787
#   PANEL_TOKEN=<管理员口令，≥12 字符>
#   PANEL_READONLY_TOKEN=<只读口令，可留空>
.venv/bin/python -m app.control
ssh -L 8787:127.0.0.1:8787 <user>@<vps>     # 然后浏览器打开 http://127.0.0.1:8787/
```

- 能做：看运行概览与日志尾部（脱敏、最多 256 KB / 1000 行）、列群看群、改群设置（模式、工具开关、
  贴纸冷却、群人设）、写入或替换 `BOT_TOKEN` 与 `LLM_API_KEY`。
- 不做：不启停机器人（凭据改完回 `restart_required: true`，需自己重启）、不写 `.env` 之外的文件、
  没有多用户账号、**不提供公网暴露方案**。
- 安全：`Authorization: Bearer` 两级口令（管理员 / 只读），口令不足 12 字符直接拒绝启动，
  凭据接口**只写不读**、永不返回明文；详见 `docs/security.md` §2.3、`docs/deployment.md` §13、ADR 0011。

## 6. 怎么改

- 先读 `AGENTS.md`（开发规则）与 `docs/README.md`（路由表：要改 X 就读哪个文件）。
- **契约优先**：行为规则在 `docs/requirements.md`，安全边界在 `docs/security.md`，工具契约在 `docs/tools.md`，
  部署契约在 `docs/deployment.md`。改代码前先确认契约，改完同步文档（`AGENTS.md` §5/§9）。
- 分层约束（有测试锁死）：适配器（`app/telegram/`、`app/control/`）只做鉴权/解析/转发，业务读写经
  `app/services/` 或既有 `app/ops/`，适配器不得直连 SQLite / workspace / 工具执行器 / 沙箱；
  Web 框架只允许出现在 `app/control/`。
- 跑测试（全离线、不需要任何 Token）：`python -m unittest discover -s tests -t .`
  → 期望 `Ran 688 tests / OK (skipped=2)`（Windows 上有 2 条软/硬链接用例跳过）。
- 设计取舍看 `docs/decisions/`（ADR 0001–0011），改动过的大方向不要重新提出。

### 6.1 换成自己的形象（默认人格是示例）

内置人格是 **DeepSeek「大肥鱼 / 鲸鱼娘」二创形象**，只是拿来当示例的默认值，换成自己的要动这些地方：

1. **不改代码**：`.env` 填 `PERSONA=<你的人设文本>`（部署侧全局），或在群里 `/settings persona_override <文本>`（**只有群主**能写，优先级最高）。
2. **改默认内置人格**：`app/llm/prompts.py` 的 `GLOBAL_PERSONA`（第 12–23 行），并同步 `docs/persona.md` §4
   ——离线测试会逐字校验两者一致，只改一处会红。
3. **改触发别名**：`.env` 的 `BOT_ALIASES`（默认空，如 `MyBot,小助手`）；代码里的 `GLOBAL_PERSONA` 自称、
   以及 `app/ops/commands.py` 第 133 行的 `/help` 文案（「叫我『大肥鱼 / 鲸鱼娘』我必应」）也提到了形象名，想彻底去个人化一并改掉。
4. **改贴纸包**：`deploy/stickers/catalog.json` 与 `deploy/stickers/README.md` 指向的是公开的 `deepseek_whale_girl` 贴纸包
   （素材不入库，需自备或换成自己的贴纸包）；不换也行，它是可选工具，库为空时 `send_sticker` 不下发。

## 7. 升级与回滚

- 升级：覆盖代码目录（保留 `.env` 与 `storage/`）→ 重启进程；启动时会自动跑数据库迁移。
- 回滚：换回上一版代码即可；迁移只向前，回滚不会删数据。
- 详细流程（含 `git bundle` 离线同步）见 `docs/deployment.md` §8。
